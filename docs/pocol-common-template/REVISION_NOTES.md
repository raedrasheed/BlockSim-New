## 3. Transaction ordering — no invented feature presented as implemented

The rule "fee density with lexicographic TxID tie-breaking" is **not** in the
original thesis, not in the original PoCol specification, and only partially
reflected in code (`Models/Transaction.py` sorts pending transactions by
decreasing fee when a block is created — with no tie-breaking, applied after the
winning event, with no cross-miner agreement). Section 5.8.2 now states this
explicitly in red: the rule is labeled a **proposed protocol requirement (reference
policy)**, the prototype's fee-descending post-hoc sort is described accurately,
and any other deterministic consensus rule (e.g., a committed transaction list
announced with B_{r−1}) is noted as equally admissible.

## 4. Mempool / common-transaction-set agreement (pass-2 edits)

Section 5.8.2 now specifies, in red, a complete mechanism (replacing the earlier
single sentence that implied deterministic sorting suffices):

1. deterministic round start at acceptance of B_{r−1};
2. bounded transaction-collection/synchronization window Δ_tx (gossip exchange);
3. eligibility cutoff: valid w.r.t. S(B_{r−1}) and received before window close;
4. deterministic selection and ordering of the eligible set (proposed reference policy);
5. identifier-based retrieval of missing committed transactions before template construction;
6. reward transaction construction and Merkle-root commitment (Section 5.9);
7. TemplateID_r as the agreement check — a miner whose TemplateID_r disagrees
   with its peers' does not mine; it resynchronizes and re-derives until IDs agree;
8. mining begins only after TemplateID_r matches the network-consistent value;
9. no centralized coordinator — agreement via peer-to-peer gossip only.

The text states explicitly that deterministic sorting alone does **not** resolve
divergent mempools, and that the window, cutoff, reconciliation, and TemplateID
gating are **not implemented in the prototype** (limitation, required extension —
cross-referenced in Chapter 6 and Section 8.5). The other pass-2 edits: the
Chapter 6 not-implemented enumeration now includes the transaction-collection
window and mempool reconciliation; the List of Figures entry for Figure 5.1 was
synchronized with its caption; a garbled phrase in the Figure 5.4 narration
("chicken scratch miner membership list") was corrected to "registered miner set".

## 6. Reward-transaction timing (verified)

transaction list (first position); committed through the Merkle root; identical

(§5.8.5, §5.9.1, §5.9.2, Figure 5.3). A whole-document sweep found **no**
remaining sentence or figure in which the winner creates, modifies, or inserts
the reward transaction after finding a nonce.
