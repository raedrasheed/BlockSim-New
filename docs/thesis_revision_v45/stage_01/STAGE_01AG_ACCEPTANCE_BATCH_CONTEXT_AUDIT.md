# Stage 1AG — Acceptance-Batch Context Audit (correction AG7)

## Intro

This audit verifies correction **AG7** — the acceptance-batch finalize seating (`BlockAcceptancePoint` /
`SeatAcceptanceBatchFinalize` / `AcceptanceBatchFinalize`, §16d/§16e) is now type-correct, result-capturing,
and generation-keyed. The type-incorrect `ORDINARY_DISPATCH(EQ.current_event_ref)` is gone; the seat owner
takes no `source_context` and seats through `ScheduleEvent`, which reads the trusted dispatcher current context
(source 1, S7); `BlockAcceptancePoint` seats first and captures the result; the finalize is keyed by
`batch_generation` so a later-delta same-timestamp arrival after a consumed finalize is never stranded. The
consensus algorithm remains **PoCol**; the mechanism under study is **the idle policy within PoCol**; the **A1
baseline (`8.420833333 kWh`)** is preserved and unchanged by this documentation-only revision. No executable
source, configuration, or experiment is touched.

All line anchors below refer to the FINAL normative tree in `STAGE_01_PROTOCOL_PSEUDOCODE.md`.

## Overall verdict

**PASS.** Correction AG7 is fully realized in the final normative tree. The type-incorrect
`ORDINARY_DISPATCH(EQ.current_event_ref)` survives only as a comment documenting its removal; the seat owner
takes no `source_context` and seats through `ScheduleEvent` on the trusted dispatcher current context (item 1).
`BlockAcceptancePoint` seats first, captures the result, registers `_seated`/`_already_seated` arrivals into the
finalize's generation batch and returns `registered`, and turns a `_seat_failed` into a candidate-scoped failure
that creates no batch entry (item 2). `SeatAcceptanceBatchFinalize` is generation-keyed, idempotent on a live
QUEUED seat, and opens the next generation on a terminal seat, matching the `batch_generation` descriptor payload
and tie key (item 3). `AcceptanceBatchFinalize` takes `batch_generation`, processes exactly that generation's
registry entry, and clears only it (item 4). A later-delta same-timestamp arrival after a consumed finalize is
covered by a fresh generation + finalize and is never stranded (item 5). No defects found. PoCol, the idle policy
within PoCol, and the A1 baseline `8.420833333 kWh` are preserved.
