**Rationale.** `apply_progress_withholding` under-reports the COMMITTED frontier, so an
intermediate committed frontier must exist when the lease is revoked. The frontier
advances only at batch completion, so a batch boundary must fall strictly inside a
primary's range: `nonce_domain_size / primary_count > batch_size`. At the reference batch
size that is `35.4 > 50`, i.e. FALSE — the original parameterisation was structurally
incapable of producing the state the hypothesis is about. At 25 the inequality holds.
This is a **structural feasibility correction made before scientific freeze**. No pilot
effect magnitude and no effect direction was used to choose the value; the only inputs
were the reachability inequality, the measured call-site state (`committed ==
lease_start`, `done = 0`), and the batch/rate arithmetic. The batch-50 `D00` control is
**not** reused for this contrast. See decision-log D-11 and D-12.
